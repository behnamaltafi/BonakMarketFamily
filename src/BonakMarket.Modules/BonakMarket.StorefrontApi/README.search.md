# Storefront search — web and mobile integration

All routes are HTTPS GET requests under /api/storefront/v1; guest access is subject to native catalog permissions. Send a valid bearer token for customer-specific pricing, or omit Authorization entirely for guest requests. An expired/invalid token yields 401, not a guest fallback.

- /search/instant?search=rice&limit=5 — call after a 250–350 ms debounce, cancel superseded requests, and ignore stale responses. Empty/short/disabled input is HTTP 200 with items: []; check enabled and minimumTermLength. limit is capped by configuration (0 when configured capacity is 0). hasMore is calculated with one extra result; no total count or price. Images may be null; resolve relative URLs against the API origin.
- /search?search=rice&page=1&pageSize=20 — paginated ProductDto results with totalCount, totalPages, hasNextPage. Empty search intentionally browses the catalog. The original /products route remains an alias. Reset page to 1 when text, filters or sort changes. Product IDs are shared with /products/{id}. The native initial sort is retained; explicit sort values use ID tie-breaking.
- /search/facets?search=rice — send the same filter values as the full results, except page/pageSize (ignored). Counts are conjunctive, not alternative/disjunctive counts; clear the selected filter before requesting its alternatives. Category counts are direct mappings. Lists can be truncated; use /categories and /brands for broader selection. canFilterPrice indicates permission; priceFilterCurrencyCode describes the base-currency range/sort basis.

Full search filters: categoryId, brandId, minPrice, maxPrice, inStock, hasDiscount, sort (Initial, NameAsc, NameDesc, PriceAsc, PriceDesc, Newest), includePrice. Use textual sort enum names in query strings. For nonblank text, omitted inStock follows admin availability settings. Explicit true selects sellable inventory (including backorders or untracked stock), false selects unavailable products; omitted on browse means no inventory restriction. Price bounds are inclusive and in base currency, using active special/catalog price before taxes, quantity discounts and customer-specific calculation. Returned price is the native displayed price (may be null when unavailable or disallowed), with its own currencyCode. Do not treat catalog filtering as a quote. hasDiscount follows the native product discount flag.

All three routes use the same scoped SQL query for text matching; only native supported fields (name, SKU, short description) and the configured search mode apply. No fuzzy search, automatic Persian character normalization, or external search index is promised. Search result names use working-language translations with a fallback to stored names. Search-as-you-type uses a smaller thumbnail.

No shared cache: results may differ by customer role/store. HTTP 400 validation, 401 invalid token, 403 access/price permission, 503 unavailable store use the existing problem response contract. Do not retry invalid requests automatically.
